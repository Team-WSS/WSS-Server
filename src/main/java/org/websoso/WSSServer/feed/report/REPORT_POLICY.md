# 신고 정책

이 문서는 피드 및 댓글 신고의 서버 정책을 정리한다.
정책 변경 시 API, DB 제약조건, 자동 처리 기준과 함께 갱신한다.

## 1. 신고 대상과 유형

- 신고 대상은 피드와 댓글이다.
- 신고 유형은 다음과 같다.
  - `SPOILER`: 스포일러 신고
  - `IMPERTINENCE`: 부적절한 표현 신고
- 현재 DB 유니크 키는 `신고자 + 신고 대상 + 신고 유형` 조합이다.
- 한 사용자는 같은 대상을 스포일러와 부적절한 표현으로 각각 한 번씩 신고할 수 있다.

## 2. 신고 가능 조건

- 사용자는 자신이 작성한 피드 또는 댓글을 신고할 수 없다.
- 사용자가 접근할 수 없는 피드와 그 댓글은 신고할 수 없다.
- 신고자와 피드 작성자가 차단 관계이면 신고할 수 없다.
- 댓글 신고 시 신고자와 댓글 작성자가 차단 관계이면 신고할 수 없다.
- 댓글 작성자와 피드 작성자가 같으면 동일한 차단 관계를 중복 검증하지 않는다.

## 3. 중복 신고와 멱등성

- 동일한 신고 요청을 여러 번 보내더라도 신고 내역은 한 건만 저장한다.
- 기존 v1 신고 API는 신규 신고에 `201 Created`, 중복 신고에 `409 Conflict`를 반환한다.
- v2 신고 API는 중복 요청도 이미 요청 목적이 달성된 것으로 보고 성공 처리한다.
- v2 신고 API는 신규 및 중복 여부와 관계없이 `204 No Content`를 반환한다.
- 중복 요청은 신고 횟수를 증가시키지 않는다.
- 중복 요청은 자동 처리 이벤트 및 Discord 신고 메시지를 추가로 생성하지 않는다.
- 멱등성을 보장하는 자연 키는 다음과 같다.
  - 피드: `feed_id + user_id + reported_type`
  - 댓글: `comment_id + user_id + reported_type`

## 4. 신고 임계치와 자동 처리

- 신고 임계치는 신고 대상과 신고 유형별로 각각 집계한다.
- 현재 모든 신고 유형의 임계치는 3건이다.
- 스포일러 신고가 임계치에 도달하면 대상을 스포일러 처리한다.
- 부적절한 표현 신고가 임계치에 도달하면 대상을 숨김 처리한다.
- 자동 처리는 조건부 업데이트로 수행하며, 이미 처리된 대상은 중복 업데이트하지 않는다.
- 임계치 이후 추가 신고가 들어오더라도 대상의 처리 상태는 유지한다.

## 5. 신고 철회

- 현재 신고 철회는 지원하지 않는다.
- 기획 요구가 생기기 전까지 신고 삭제 API를 제공하지 않는다.
- 추후 철회를 지원하더라도 신고 내역을 물리 삭제하지 않고 상태로 관리한다.
- 철회된 신고를 집계에서 제외하더라도 이미 처리된 대상은 자동 복구하지 않는다.

## 6. 이벤트와 알림

- 신규 신고가 커밋된 이후에만 신고 횟수를 다시 집계하고 자동 처리 여부를 판단한다.
- 신고 자동 처리는 `AFTER_COMMIT` 이벤트를 비동기로 실행한다.
- 자동 처리 실패는 신고 API 응답에 영향을 주지 않는다.
- 현재 비동기 자동 처리 실패에 대한 재시도와 유실 복구는 지원하지 않는다.
- 신고 메시지 생성 책임은 report 영역에 둔다.
- notification 영역은 생성된 메시지의 외부 전송만 담당한다.

## 7. 삭제와 감사 이력

- 댓글 삭제 시 해당 댓글 신고 내역을 먼저 삭제해 FK 제약조건을 해소한다.
- 피드 삭제 시 피드 및 댓글 신고 내역도 함께 정리한다.
- 대상이 삭제되면 해당 신고 이력을 보존하지 않는다.
- 신고 생성 시각과 별도의 처리 상태는 저장하지 않는다.

## 8. Deprecated API

- 기존 v1 신고 API는 클라이언트 호환성을 위해 기존 응답 정책을 유지한다.
- 멱등 신고 API는 `/v2` 경로로 제공한다.
- 신규 댓글 신고 API는 `commentId`만으로 댓글에 접근한다.
- 기존 `feedId + commentId` 기반 API는 Deprecated 상태로 유지한다.
- 기존 `feedId + commentId` 기반 API는 클라이언트 전환 완료 후 제거한다.
